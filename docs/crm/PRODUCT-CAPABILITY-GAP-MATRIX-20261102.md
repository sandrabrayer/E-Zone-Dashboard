## C. Important source-versus-screen distinctions
1. **Case visibility is not debt validity.** A released patient may have a real historical balance, an inferred cycle, a manually stamped payment, or a display/filter discrepancy. Classify by `sourceType`, period `coverageStart/End`, stay `entryDate/exitDate`, payment `patientUid/patientId`, status, write acknowledgment, asOf and role. Never silence collections solely by hiding released patients.
2. **Exit on a billing anchor requires explicit policy.** The classic `patientStayCoversDate` includes exit day; the date-of-entry and last day can coincide with a cycle start. This may create a projected period even if no stored Payments row exists. The monetary outcome depends on the agreed refund/billing policy; do not change a rule as a UI bug fix. Add synthetic boundary tests and financial signoff.
3. **No-show and cancelled are distinct operations.** Existing manager `no_show` display merges them; do not incorrectly translate either into 'meeting held' or auto-close.
4. **A missing data source is `unavailable`, not 0.** `myDay` and helper queues already follow this pattern for some sources; extend acceptance to every card and cross-app feed.
5. **No financial or clinical PII in GitHub.** This audit uses only function/path references and generic scenarios.
